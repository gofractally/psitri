Direct or DWAL?

ARM not measured: the Mac did not satisfy the idle gate.

For mixed writes, also select reader throughput: large DWAL commits delay fresh snapshot capture. At batch 10,000, native DWAL readers delivered 101K reads/s versus MDBX’s 8.26M.

Matched work

100,000 accounts. One million transfers per timed write phase. Each transfer reads two balances and updates both. Eight-byte keys and values; identical deterministic traces. Batch size also governs loading and warmup.

Validation before ranking

Every plotted cohort passed rollback, snapshot stability, read-your-writes, exact account state, balance conservation, cardinality, and clean-close/reopen checks. This does not test power-loss recovery.

Same base, different write path

Both DWAL paths buffer into ART and merge into the Large Engine. Each commit submits its WAL record to the OS without fsync; log rotation and close retain full barriers. Direct storage has no WAL. Read promotion is disabled; pinned-cache budget is 256 MiB. This dataset fits in RAM.

Diagnostic, not a release claim

One isolated process at a time after a sustained idle check. Direct bars come from the preceding sweep on the same host; MDBX and both DWAL paths were measured in this sweep. One run per configuration, without uncertainty intervals. Include close/drain time and memory when evaluating the buffering tradeoff.
